# Shipping calculator + order tracking: setup and handover

Two Worker-backed pages on the dev site:

- `shipping-calculator.html` — destination + weight + size → live carrier rate table
- `track-order.html` — tracking/order number → scan-event timeline (also accepts `?no=...`)

They are generated by `scripts/build_app_pages.py` from the `our-pricing.html`
chrome. **Edit the script, not the built HTML**, then run:

```bash
python3 scripts/build_app_pages.py
```

## How it is wired

The PFC Open Platform (`oms.pfcexpress.com`) is a plain-http ASMX/SOAP service
that needs a secret key, so a static page cannot call it directly. A small
Cloudflare Worker (`worker/index.js`) holds the key server-side and returns
clean JSON. `wrangler.jsonc` runs the Worker **only for `/api/*`**
(`run_worker_first`); every page, image, `robots.txt` and `sitemap.xml` path is
still served straight from static assets, exactly as before.

| Route | Upstream PFC method | Needs key |
|---|---|---|
| `GET /api/health` | — | reports `configured` true/false |
| `GET /api/countries` | `getCountry` | yes |
| `GET /api/rate?country=&weight=&l=&w=&h=` | `getFeeByCWV` | yes |
| `GET /api/track?no=` | `getOrder_Track` (+ `getPackage` for header) | yes |

Until the key is set, the pages run in **preview mode**: an amber badge, and a
clearly-labelled **sample** table/timeline so the team can see the layout. No
fabricated data is ever shown as live.

## To go live: add the credentials (NEVER commit them)

Create the key in the PFC user centre ("enable the API service"), then set them
as Cloudflare secrets on the Worker:

```bash
wrangler secret put PFC_SECRET_KEY     # the PFC API identifier
wrangler secret put PFC_CUSTOMER_ID    # e.g. 80000
```

Optional config (plain vars, not secret):

- `PFC_API_BASE` — upstream base, default `http://oms.pfcexpress.com/webservice/APIWebService.asmx`
- `RATE_FX_USD` — RMB to USD multiplier to add a USD column (e.g. `0.141`); omit for RMB only

For local `wrangler dev`, copy `.dev.vars.example` to `.dev.vars` (gitignored)
and fill in real values. The Worker ignores any `secretkey` sent by the browser;
it only ever reads the key from its own environment.

## Live status (verified 21 Oct 2026, key wired in Cloudflare)

- **Upstream base:** the documented `oms.pfcexpress.com` host is dead (302 to a
  404). The live ASMX service is `https://www.china-fulfillment.com/webservice/APIWebService.asmx`
  (set as the Worker default). GET works; responses are `<string>`-wrapped JSON.
- **Params** confirmed against the WSDL: `getCountry(secretkey)`,
  `getFeeByCWV(country,weight,volume,customerid,secretkey)`,
  `getOrder_Track(Orderid,secretkey)`, `getPackage(orderNO,customerid,secretkey)`.
- **Working now:** `getCountry` returns 330 countries (United States = `221`),
  and `getOrder_Track` + `getPackage` respond — so **tracking is live** (needs a
  real order/tracking number to show events).
- **BLOCKED:** `getFeeByCWV` (the rate query) returns *"Access without
  permission, please mail sales@pfcexpress.com for query permission"*. The same
  key works for every other method, so this is a **per-method permission gate on
  PFC's side**, not a code or customer-ID problem. **Action: ask PFC (or the PFC
  account manager) to enable the price/fee-query (`getFeeByCWV`) permission on
  this API key.** Once enabled the calculator works with no code change.
- **USD column:** done. The Worker converts RMB to USD at a live mid-market rate
  (jsdelivr `cny.usd`, pages.dev fallback, cached 12h, baked fallback), shown as
  a second column with the rate noted. A fixed `RATE_FX_USD` overrides it.

Still to confirm once the rate permission is on: that `country=221` (the
`Base_placeId` code) and `volume = L x W x H` in cm3 return the expected totals
(cross-check against the back-office `OrderFeeSearch.aspx`: US, 0.5 kg,
10x10x10 should give PFCEXPRESS around RMB 74.50).

## Production note

Production is IIS/ASP.NET, not Cloudflare, so these Worker-backed pages are not a
copy-paste CMS port like the static pages. Production already has the original
calculator at `/Manage/.../OrderFeeSearch.aspx`. Porting to the live domain needs
its own plan (proxy via the ASP.NET backend, or point the live pages at the
Worker). Kept off `CMS-UPDATE-CHECKLIST.md` until that is decided.
